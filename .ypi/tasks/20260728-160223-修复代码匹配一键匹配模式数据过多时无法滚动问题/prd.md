# PRD — 代码匹配长结果列表滚动修复

## 目标与背景

Yolk Pi Web 的文件编辑器支持通过工具栏、快捷键和点击手势查询定义、引用与 Java 实现。后端最多可返回 50–120 条结果，但当前结果展示只依赖一段内联 `maxHeight/overflow`，没有明确的 flex 高度链、唯一滚动容器和跨视口验收。用户在大量结果场景无法访问列表下方数据。

目标是在不改变匹配数据、排序、快捷键与打开文件行为的前提下，让长结果列表在桌面、低高度窗口和窄屏上始终可滚动、可达，并保留可用的代码编辑区域。

## 用户价值

- 使用一次点击/快捷键完成代码匹配后，可以查看全部已返回结果，而不是只看到首屏几条。
- 滚动结果时不会把整个工作台带走，也不会失去当前编辑上下文。
- 鼠标、触控板、触屏和键盘用户都能到达末条结果。
- 少量结果、空结果和错误提示维持当前简单体验。

## 范围内

1. `FileViewer` 符号匹配共享结果区的纵向布局与滚动修复。
2. 定义、引用、Java 实现以及点击/快捷键触发路径共同生效。
3. 桌面、低高度、`≤640px` 与 375px 窄屏适配。
4. 长结果、短结果、空、错误、loading/连续搜索状态。
5. 结果行点击打开目标文件与指定行号的回归。
6. 必要的前端文档、focused layout contract test/静态断言与人工浏览器验收。

## 范围外

- 修改 definitions/references/implementations 搜索算法、结果上限、排序或响应 schema。
- 引入分页、无限加载、虚拟列表、结果筛选、分组或搜索框。
- 新增可拖拽结果区高度、持久化高度或关闭按钮。
- 重构 Monaco、文件编辑/保存、SSE watch、Diff/Preview、Add Chat。
- 修改 Settings 中编辑器快捷键配置。
- 修复仓库外名称相似的“代码匹配”页面。

## 需求与验收标准

### R1 — 长结果存在独立纵向滚动

当返回结果总高度超过结果区可用高度时，结果区内部必须产生纵向滚动；用户可从第一条滚到最后一条。

**验收：** 使用 50、80、120 条模拟结果，滚轮/触控板/拖动滚动条均能到达末条；列表不会被父级 `overflow: hidden` 裁掉。

### R2 — 布局高度链明确

文件查看器根、结果面板、结果列表和编辑器内容区必须形成可计算的 flex 高度链。结果列表是唯一纵向 scroller，编辑器内容区保留 `min-height: 0` 和独立滚动能力。

**验收：** 结果面板不覆盖状态栏或 Monaco；窗口高度降低时不会把编辑器完全挤出；结果关闭/清空后编辑器恢复剩余空间。

### R3 — 三类查询与一键路径一致

`definitions`、`references`、`implementations` 复用同一滚动结果区；工具栏、`Cmd/Ctrl+Click`、`Shift+Click`、`Shift+F12`、`Cmd/Ctrl+F12` 不得产生不同布局。

**验收：** 每种 endpoint 至少验证一次长列表；触发方式只改变查询语义，不改变滚动可达性。

### R4 — 滚动隔离

在结果列表内部滚动时，滚动输入优先作用于列表；到达边界后不应造成明显的外层工作台滚动跳动。触屏支持惯性滚动。

**验收：** 桌面 wheel/trackpad 与移动端 touch 均可操作；结果列表滚动位置变化，外层 Chat/右抽屉不发生意外位移。

### R5 — 滚动可发现

长列表应预留稳定的滚动槽，系统允许时显示可识别的滚动条；不得通过隐藏 scrollbar 的规则让用户误以为结果不可滚。

**验收：** Chromium/macOS/Windows 常规配置下，滚动条遵循系统策略但不被组件 CSS 隐藏；内容宽度不因滚动条出现/消失明显跳动。

### R6 — 行内容与打开行为不回归

结果行继续显示 kind、相对路径/行号与 preview；长文本省略，完整路径保留在 title；点击仍调用 `onOpenFile(filePath, fileName, line)`。

**验收：** 首条、中间条、末条均可点击并定位正确文件/行；无 `onOpenFile` 时不伪造可用导航。

### R7 — 状态不回归

loading、空结果、请求错误、连续搜索、文件切换后的清理行为保持正确。空/错误短内容无需制造多余滚动。

**验收：** 搜索中按钮仍禁用；空态/错误态完整可见；切换文件清除旧结果；新查询覆盖旧查询的现有语义不因本次布局修复改变。

### R8 — 响应式与低高度

结果面板最大高度同时受组件与视口约束；375px 宽屏和低高度窗口不得横向溢出或遮挡关键编辑区域。

**验收：** 至少验证 1440×900、1024×600、640×480、375×667；结果行三列保持单行省略，纵向仍可滚到底。

### R9 — 可访问性

结果区提供可识别区域名称；结果行保持原生 button 与可见 focus；Tab/Shift+Tab 聚焦到视口外结果时，滚动容器自动把该行带入视图。状态不能只靠颜色表达。

**验收：** 键盘可依次访问并激活结果；焦点环可见；屏幕阅读器能识别“代码匹配结果”区域和结果按钮含义。

### R10 — API 与安全边界不变

本任务不修改 API 请求参数、允许根校验、结果上限、文件读取边界或返回字段。

**验收：** route 文件无需生产行为改动；前端仍只消费既有 allowlisted result fields。

## 非功能要求

- 不为最多 120 条结果引入虚拟化依赖。
- 不新增运行时配置或持久化数据。
- 优先使用稳定 class + `app/globals.css`，减少无法回归的复杂内联布局。
- 遵循现有 `--bg-*`、`--border`、`--text-*` 主题变量。
- 不覆盖或重置工作树中与本任务无关的用户改动。

## UI 门禁与审批

本任务改变用户可见交互，必须由 UI 设计员提交 HTML 原型，并由用户明确审批。批准前仅保留规划产物，不进入 `implementing`，不修改生产代码。

## 未决问题

1. 请主会话确认“代码匹配 / 一键匹配”是否确指 `FileViewer` 的符号导航结果区；当前代码证据支持该映射。
2. 默认建议本次只修滚动，不增加结果计数、关闭按钮、拖拽改高等功能；若需要，请在审批时明确扩展范围。
